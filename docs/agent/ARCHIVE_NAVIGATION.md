# Archive rebuild: panel navigation slice

`src/pages/archive-rebuild.astro` owns the existing markup/CSS and boots `bootArchiveNavigation()` only on this route. Dependency direction is **page → browser adapter (`src/lib/archiveNavigationBrowser.ts`) → use case (`src/lib/archiveNavigation.ts`)**. The use case currently imports nothing; its `NavigationOutput.apply(NavigationCommand)` port speaks only panel names, work IDs, focus intents and exit tokens. The browser adapter implements that port using the page's elements, animation/focus APIs, thumbnail renderer and existing selection/filter stores. Wheel mechanics, audio, filter computation and Point preview remain their existing integrations; they are not new core dependencies.

Example trace: Point activation → adapter checks visibility, guards the native link, supplies ID/origin → `openWork` emits `select-work`, `dismiss-preview`, `present(detail)`, `render-detail`, `focus(detail-close)` → adapter updates store, thumbnail/link, DOM and focus. Escape → use case synchronously clears active panel, emits `present(null, exiting:detail)`, `begin-exit(token)`, `focus(origin)`; adapter makes the visual remnant inert and starts the 100ms animation. A rapid reopen emits `cancel-exit(token)` before the new `present`; late `finishExit(token)` is ignored. Reduced motion, outside click and filter invalidation close without an exit. Wheel selection changes an already open detail's contents, not its originating focus target.

Selection/input on `/archive-rebuild/` uses a separate, browser-free decision boundary: `src/lib/archiveSelection.ts` takes Point activation, Wheel title/station, filter and preview intents and reads the current committed ID through an output port. `src/lib/archiveSelectionBrowser.ts` is the **shared** output adapter used by the clean Wheel and navigation's `select-work` command. It alone commits through `workSelectionStore` and emits `archive-wheel-selected` *after* synchronous store subscribers, only for a changed, non-null rendered Wheel station. Its temporary origin guard prevents Wheel subscriber callbacks from cancelling their own motion; it does not hold a second selected ID. Point activation deliberately reaffirms even the same ID; a Wheel title commits without a Wheel-selected preview event. Filter invalidation clears the ID, while the Wheel's visible fallback remains only a display index. The filter decision keeps the prior index/offset if the list is empty; for a nonempty list it sets the retained/clamped station *before* the output port clears the store and synchronously notifies subscribers. Restoring a list never commits that visual fallback. Hover/focus Point/Card preview is transient and never a store commit; link/focus/availability guards remain in the browser adapters. The shared Wheel's old and trial routes still use their existing paths.

Wheel-packet ownership on `/archive-rebuild/` has its own pure decision boundary in `src/lib/archiveWheelInput.ts`. The Wheel script classifies DOM targets, reads the live SVG box and clock, manages the ownership timeout, and applies preventDefault/rotation. The core decides direct-vs-document priority, coordinate-scoped continuation/anchor refresh, pointer release and clipped half-ellipse membership; only a fresh passive document packet requests geometry. The same 420ms association constant is shared with the existing motion code. Non-clean Wheel behavior and drag/touch physics remain in the component.

To add a new selection trigger, translate it into an intent at the browser edge, decide ID semantics in `archiveSelection.ts`, and implement any store/browser effects in its shared output adapter; do not add a parallel selected ID. To add a new navigation trigger, translate its browser event to an existing use-case method (or add a semantic method/command and fake-port test first); implement DOM/focus/animation behavior in the adapter. Do not import browser types, stores or adapter paths into the use case. `tests/archive-navigation.test.mjs` runs the bundled ESM use case in browserless Node with a fake output and checks its transitive module graph for page, component, browser-adapter and store dependencies (pure helpers remain allowed); the existing browser suites remain the UI-equivalence checks for the lead.

## Wheel motion boundaries (current `/archive-rebuild/`)

Follow a consumed packet through `src/components/works/ArchiveWheel.astro` (mounted with `centredTrial cleanTrial` by `src/pages/archive-rebuild.astro`):

1. **Units at the browser edge:** direct Wheel and clean document-fallback listeners first decide ownership (`src/lib/archiveWheelInput.ts`), then consume with `preventDefault()` and call `wheelDeltaPixels(event, window)` from `src/lib/archiveWheelDelta.ts`. The helper reads `deltaMode` once, live `window.innerHeight` only for page mode, then `deltaY` once; pixel/unknown modes use ×1, line ×16, page ×viewport height, retaining sign and fractions. Unclaimed/protected packets never reach conversion. This is a consumed-`WheelEvent` conversion at the boundary, not a new motion clock or an input-ownership rule.
2. **Speed window on the clean path:** `scrollContinuously` in `ArchiveWheel.astro` supplies `estimateWheelSpeed` in `src/lib/archiveWheelSpeed.ts` with the sample history, raw and ±880-bounded pixels, `performance.now()` time, existing backlog flag and 110px/station scale. The pure function returns a new ≤500ms sample window, speed and last gap; raw packets over 220px contribute zero distance but retain their timestamp, the first retained sample anchors rather than contributing distance, a strictly <60% taper uses the last packet/gap, and only 12–500ms measured intervals without backlog yield velocity (clamped by `archiveWheelCoast.ts`). The component still decides gesture/reversal resets, light-distance mapping, backlog/catch-up, whether to coast and the settle timeout/delay; the speed core does not schedule or publish anything.
3. **Coast projection and frames:** `startCoast` passes measured speed, delivered input budget, already rendered offset and live visible-item count to `projectCoast` in `src/lib/archiveWheelCoast.ts`; it returns clamped natural reach, rounded detent and at-rest status. Each clean coast RAF passes accumulated elapsed milliseconds and the live count to `advanceCoast`, which returns the next clamped offset and stop decision (including detent capture). The pure coast module also exports the shared velocity clamp; it owns neither the clock nor RAF. `ArchiveWheel.astro` retains motion state, timeout/RAF scheduling and cancellation, filter/close/reduced-motion resets, DOM layout/label transforms, and rendered-station selection notifications via the existing selection adapter/store. Keep DOM, actual time, gesture bookkeeping and rendering outside these numeric helpers.

The shared component's **legacy** `/` and `/archive-trial/` Wheel listeners also convert consumed deltas, but `rotateByPixels` then accumulates signed pixel parts, updates an offset on RAF and snaps on its own timer; it does **not** use the clean wheel speed window or coast pipeline. Clean pointer/touch release is another input: its local `quietVelocity` uses a separate 125ms offset-sample window and may feed `startCoast`; it is not part of the wheel-speed extraction or a touch bug fix. Do not unify those paths just because they share coast math.
